# SydForge + Sydney Experiment — Deep Audit (2026-11-22)

**Scope:** `Z:\GITHUB\_GAMES\SydForge` (game/runtime) and `Z:\GITHUB\_EXPERIMENTS\Sydney`
(geographic experiment and pipeline), with `FUTURE_PLANS.md` (CityForge/HARBOURLINE)
as the forward-looking brief.
**Mode:** read-only except for the creation of this report. No code, data, scene or
configuration was modified; no commit or push was made. Headless Godot tests were
executed in place (they write only Godot's ignored `.godot/` cache).
**Verification environment:** Godot 4.7.2 stable
(`Godot_v4.7.2-stable_win64_console.exe`), Windows, `--headless --path . --script`.

## 1. Executive summary

1. **The "two projects" in `FUTURE_PLANS.md` are now one working vertical slice.**
   The plan names Project B as `Z:\GITHUB\_GAMES\New folder` / "Splooge" / "BOOMTOWN —
   District Zero". That repository is the present SydForge: `3f27480` is literally
   `docs: rebrand the project as SydForge and rebuild the README`, and `project.godot`
   now declares `config/name="SydForge"`. The plan's recommendation to "replace
   `district.gd::build_city()` with a world loader" (Sydney audit §D.3, 19 Nov 2026)
   is **already implemented** — `scripts/district.gd::build_city()` loads
   `SydneyWorld`, and `scripts/sydney_cbd_district.gd` builds a full OSM city. The
   brief is accurate about the *destination*, but stale about the *starting point*.
2. **The data handoff from Sydney to SydForge is real and partly byte-identical.**
   `sydney/world/stage_a/world.json` and `sydney/world/inner_west/height.bin` are
   exact MD5 matches of the Sydney pipeline exports. Stage B is a deliberate fork:
   the game copy adds 1,329 roads, 3,078 footpaths, 1,556 crossings, 2,661 buildings
   and 372 parks west of Broadway, using a data-only splice that has **no committed
   regeneration script** in either repository.
3. **The working tree is a substantial, coherent but fragile uncommitted batch.**
   SydForge has 14 modified tracked files (+585/−177 lines) and **294 untracked
   files**, including 11 load-bearing `.gd` scripts, 7 new test suites, new business
   POI data and 5 new design docs. Four preloads in *tracked, modified* files point
   at *untracked* new files. Committing only the tracked diff would break the game.
   The Sydney experiment is also dirty: its Stage A/B builders, exports, DEM cache,
   audit and `FUTURE_PLANS.md` are all untracked.
4. **The uncommitted work is genuinely tested.** I re-ran nine headless suites: all
   nine passed (149/0 parse, 2,350/0 rail physics, 54/0 CBD expansion, 32/0
   headlights, 20/0 business POIs, 17/0 lighting/pause, 13/0 station components,
   12/0 settings, 5/0 rail-cut decks). Two legacy suites still fail exactly as the
   project's own notes predicted (`main_game_test` 39/18, `wanted_system_test` 6/3).
5. **A concrete data-integrity defect was found:** Stage B's `stats` block was not
   recomputed after the Parramatta Road splice. It declares 378.86 km of roads and
   587.75 km of footpaths, while summing the exported geometry gives **511.57 km**
   and **761.58 km**. `README.md` repeats the stale figure. This is evidence that
   the "source → generated output" boundary is currently managed by hand.
6. **Against CityForge, SydForge is strong on A (city generation) and C (gameplay),
   partial on B (living world, no navmesh/chunk streaming), and effectively missing
   D (StyleForge as a theme system).** None of the eight documents requested by
   `FUTURE_PLANS.md` §9 exists yet; the 71 KB Sydney audit covers only part of the
   discovery/cross-reference work.

### 3.2 Generation pipeline — Python, in the Sydney repository

`sydney-osm-world/` contains 23 Python scripts (largest: `build_inner_west.py`
69 KB, `build_stage_b.py` 66 KB, `build_stage_a.py` 45 KB). Stages: `query_sydney.py`
/OSM MCP + Overpass → `normalize_osm.py` (stable IDs, tag preservation, 3 m snap
intersections, ring stitching) → `build_world_spec.py` → `build_stage_a.py` /
`build_stage_b.py` / `build_inner_west.py` (road graph, derived footpaths, block
subdivision, districts, JSON exports) → `audit_stage_a_geometry.py` /
`audit_stage_b_geometry.py` / `test_stage_a_export.py` (validation) and
`collect_dem_inner_west.py` (AWS terrarium tiles). `common.py` owns projection;
`stable_rng(seed_text)` (SHA-256-seeded) in `build_stage_b.py` makes subdivision
deterministic; `generatedAt` timestamps in the output are not.

Requirements are deliberately light (stdlib + `uv`-managed venv, vendored Three.js
viewer). This is a good candidate for CityForge's `packages/geo` core; it is
Sydney-specific only in its config, seed list and bbox, not in its projection maths.

### 4.4 Data-integrity finding (not a code change)

`stage_b/world.json` was extended with the Inner West strip without recomputing its
`stats` block:

| Metric | Declared in `stats` / README | Summed from exported geometry |
|---|---|---|
| Road centreline | 378.86 km | **511.57 km** |
| Footpath centreline | 587.75 km | **761.58 km** |

`stats.buildingsFromOsm` (896) + `stats.buildingsGenerated` (8,104) = 9,000, the
*pre-splice* building count, while `buildings.length` is 11,661. There is no
validation test that recomputes these aggregates. This is a small but important
breach of the plan's "validate generated geometry and asset references" rule.

## 6. Realistic roadmap toward CityForge / HARBOURLINE

Ordering follows what the code actually supports; each phase assumes the previous
one is accepted. No phase requires a second engine or a multiplayer stack.

### Phase 0 — Stabilise what exists (no new features)
- **Deliverables:** one atomic snapshot of the current overhaul (all 14 modified + 11
  load-bearing new `.gd` + `businesses.json` + 7 new tests + 5 docs), ignoring
  generated `.import`/`preview_tmp` noise; add `.gitattributes`; fix stale doc
  claims (`todo.md` last commit, `RAIL_EXTENSION_PLAN.md` reference); recompute or
  regenerate Stage B `stats`; commit the Sydney pipeline that generates the data.
- **Depends on:** user approval to commit (this audit did not commit).
- **Acceptance:** clean clone parses (149/0), all nine suites above pass, both repos'
  generators are versioned, `git status` contains no load-bearing untracked files.
- **Risk:** losing the batch or committing it in pieces is the single largest
  near-term risk to the project.

### Phase 1 — Produce the missing planning set (§9)
- **Deliverables:** in a new planning directory (do not restructure either original
  repo): `DISCOVERY_REPORT.md`, `SYSTEMS_CROSS_REFERENCE.md`,
  `CITYFORGE_ARCHITECTURE.md`, `CFWORLD_SPEC.md`, `ROADMAP.md`,
  `FIRST_VERTICAL_SLICE.md`, `RISKS_AND_OPEN_QUESTIONS.md`, `NEXT_AGENT_TASK.md`.
  Reuse the 19 Nov Sydney audit and this document as evidence sources.
- **Depends on:** Phase 0 snapshot so line references are stable.
- **Acceptance:** every subsystem record uses the brief's status vocabulary and
  cites a file path; duplicated/conflicting systems are named explicitly (e.g. two
  business layers, two facade tiers, two light-ownership paths).

### Phase 2 — World package contract and regeneration
- **Deliverables:** a versioned `cfworld` manifest that wraps the existing JSON
  schema with migration from `splooge-sydney-world` v1; a scripted, provenance-
  recording Stage B splice in the Sydney pipeline; a headless validation suite that
  recomputes counts/lengths, checks ODbL fields and compares a regenerated world to
  the committed one.
- **Existing files:** `sydney/sydney_world.gd::_valid_bounds` / `load_world`,
  `scripts/build_stage_b.py`, `scripts/audit_stage_b_geometry.py`,
  `tests/cbd_expansion_test.gd`.
- **Acceptance:** deterministic rebuild (timestamps excluded) reproduces geometry;
  `stats` match computed totals; overwriting the game copy never loses the west strip.
- **Risk:** changing the format label too early; keep the old reader for one release.

### Phase 3 — Terrain (Priority 1 from `todo.md`)
- **Deliverables:** re-base ground cells, road/footpath ribbons, building foundations,
  parks, furniture and all collisions onto the AWS terrarium grid already committed
  as `height.bin`; preserve authored bridge/Opera House/station elevations; add
  road-corridor flattening.
- **Depends on:** Phase 2 (else regeneration destroys the work).
- **Acceptance:** `tests/cbd_rail_*`, `sydney_physics_test`, `cbd_expansion_test` and
  a new terrain-continuity suite all pass; no gaps at the rail cutting; authored
  landmarks keep their current heights.
- **Risk:** highest-cost phase; do it once, after the package contract exists.

### Phase 4 — StyleForge extraction
- **Deliverables:** promote `cbd_neon_city.gd`, `cbd_arch_slice.gd`,
  `cbd_district_anchors.gd`, `cbd_skyline_heroes.gd` into theme presets with a
  world-agnostic interface; keep Origin as the default; prove PS2/Neon permutations
  on the same Stage B JSON.
- **Acceptance:** a theme change alters architecture, materials, vegetation, vehicles
  and lighting without editing geographic data or gameplay scripts.
- **Risk:** tempting to bundle with terrain; keep separate so regressions are legible.

### Phase 5 — Living-world and gameplay decoupling
- **Deliverables:** replace concrete `SydneyWorld`/`CbdWorld` parameter types with a
  small world interface; make spawn/density/POI/route sources data-driven from the
  world package; add the missing navmesh over `pedestrianGraph`; make the settings
  and pause modules reusable by other districts.
- **Acceptance:** Inner West loads as a spawn within a bounded build-time budget;
  traffic and pedestrians work against a world loaded from any region.
- **Risk:** broad refactor; gate on Phase 3/4 acceptance and keep gameplay suites green.

### Phase 6 — Performance, streaming, human verification
- **Deliverables:** chunked generation for the 5 × 5 km city, frame-time budget for
  daylight (~128 ms today), multi-hour soak test, visual pass on storefronts/
  headlights/pause, manual drive of the 14 rail decks, fix the two stale suites or
  formally retire them.
- **Acceptance:** measured numbers in `PERFORMANCE_AUDIT.md`; no `main_game_test`/
  `wanted_system_test` red baselines left unexplained.

### Phase 7 — Editor, SDK, templates (defer)
- Graphical editor, Godot template package and external workflows only after a
  second region proves the platform claim. No Unreal/Rust adapter, no multiplayer
  architecture before then, per the brief's own guardrails.

**First milestone remains HARBOURLINE — Sydney** (brief §6): it is already partly
built — real roads, buildings, landmarks, player, vehicles, camera transitions,
pedestrians and traffic exist. What remains for a credible slice is terrain, chunk/
performance work, and the packaging/validation discipline that makes the result
reproducible.
